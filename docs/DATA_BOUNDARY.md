# Public Data Boundary

This repository reconstructs the software workflow used for a research
study involving polysomnography (PSG) data.

The original participant-level PSG recordings are not distributed in
this public repository.

## What is public

The repository may contain:

- source code;
- configuration files;
- historical source-code references;
- documentation;
- artificial participant-level feature tables;
- synthetic PSG generators;
- tests;
- generated figures or tables that do not expose protected data;
- software-demo outputs when they are explicitly intended for public use.

The checked-in example feature tables under:

`examples/synthetic_features/`

are fully artificial.

Their participant identifiers use the `SYN###` format and are not tied
to real study participants.

## What must remain private

The public repository must not contain unauthorized:

- raw PSG recordings;
- MNE FIF files derived from study participants;
- EDF, BDF, EEG, BrainVision, or similar physiological recordings;
- participant-identifying metadata;
- protected clinical records;
- locally exported participant feature tables;
- participant-derived screenshots;
- private correspondence;
- workstation-specific data paths;
- credentials or local configuration secrets.

## Original study data

The original PSG dataset is not required to inspect the repository
architecture or exercise its public software interfaces.

Access to the historical clinical dataset is outside the scope of this
repository and remains subject to the applicable institutional,
research, privacy, and data-use requirements.

## Synthetic software demonstration

A complete artificial software demonstration is provided.

The synthetic workflow generates local MNE Epochs files, extracts graph
features, and runs a lightweight modeling smoke test:

```text
fully artificial PSG
        |
        v
local synthetic FIF files
        |
        v
historical-compatible feature extraction
        |
        v
participant-level feature CSV
        |
        v
lightweight Random Forest smoke test
        |
        v
metrics and feature-importance tables
```

Run it with:

```bash
python scripts/run_synthetic_demo.py \
    --work-dir outputs/synthetic_demo \
    --participants 10 \
    --overwrite
```

The generated signals and metrics have no clinical or scientific
interpretation.

They exist only to demonstrate that the software components connect
correctly.

## Git boundary

Raw PSG-like binary formats and generated runtime outputs are excluded
from version control.

The repository audit checks that no raw PSG files are tracked.

The synthetic FIF files generated by the demonstration remain local and
must not be committed.

## Scientific reproduction boundary

The repository distinguishes three different goals:

### Software reproduction

Can the reconstructed code execute its intended processing workflow?

The synthetic demonstration supports this type of verification.

### Behavioral historical reconstruction

Does the cleaned implementation preserve the behavior observed in the
historical source code?

The preserved source implementations and automated tests support this
type of verification.

### Exact published-result reproduction

Can the exact published numerical results be regenerated?

That requires the appropriate original research inputs and recorded
experimental state.

The repository does not claim exact published-result reproduction from
the public synthetic data.

In particular, the historical standalone modeling implementation
contains unseeded stochastic operations, so exact numerical replication
cannot be inferred from source code alone.
